# World History Quiz — web version

The browser version of **World History Quiz** (Android app
`com.kysystemstudio.historychallenge`). It has the same 5,250 questions,
150 stages, rules and look as app version 1.2.0.

Live: https://cgpark1109.github.io/world_history_quiz_web/

Plain static HTML, CSS and JavaScript: no build step, no frameworks. All paths
are relative, so the folder can be served from any sub-path.

## Files

| Path | What it is |
| --- | --- |
| `index.html` | Page shell, meta / Open Graph tags |
| `app.js` | The whole app: routing, screens, quiz logic, progress |
| `style.css` | Styles (colours and sizes from the app's theme) |
| `icons.js` | Material icon paths, generated by `tools/make_icons.py` |
| `assets/` | Emblem, favicons, Open Graph image (copied from the app) |
| `data/<era>_<type>.json` | Questions, copied unchanged from the app's `assets/data` |
| `data/notices.json` | Notices, copied from the app |
| `data/manifest.json` | App version and per-file counts, written by the sync script |
| `tools/` | Sync and check scripts (not used by the site itself) |

Only the data file for the era and quiz type the player opens is downloaded
(90–120 KB gzipped each), never all 15.

## Updating after an app release

The Flutter app is the source of truth. After the app's questions, notices or
branding change:

```sh
python tools/sync_from_app.py ../world_history_quiz     # path to the app repo
python tools/check_data.py ../world_history_quiz        # integrity + equality with the app
git diff --stat                                          # review, then commit
```

`sync_from_app.py` copies the 15 question files (minified, same records),
`notices.json`, the emblem, the app icon (favicons) and the store feature
graphic (`og-image.jpg`), and writes `data/manifest.json`. Re-running it with
unchanged app files changes nothing. Needs Python 3.9+; Pillow is optional
(only for the PNG favicons and the Open Graph image).

It also reads the app's `lib/constants.dart` and prints a **WARNING** if the
number of stages per era, questions per session or the clear score differ
from the constants at the top of `app.js`. If you see one, update `app.js`.
Rule or screen changes in the app's Dart code (not just data) still need to be
ported by hand; the relevant code is marked with the Dart class it mirrors.

To regenerate `icons.js` (only when adding an icon), run
`python tools/make_icons.py`; it needs `fontTools` and a Flutter SDK on PATH.

## Checks

```sh
node --check app.js && node --check icons.js
python tools/check_data.py ../world_history_quiz

# serve the parent folder to test a sub-path, then check every referenced file
cd .. && python -m http.server 8000
node world_history_quiz_web/tools/check_site.mjs http://127.0.0.1:8000/world_history_quiz_web/
```

`check_site.mjs` fetches the page and every asset referenced from HTML, CSS
and JS (including every `fetch()`ed data file) and fails on any 404 or on a
root-absolute path.

## Behaviour notes

* **Rules** (from the app): 10 questions per session drawn from the stage's
  pool of 35; 6/10 clears a stage and unlocks the next; stars on the result
  screen: 10/10 = 3, 8–9 = 2, 6–7 = 1.
* **Hints**: in the app a hint costs a rewarded ad. On the web hints are free,
  still one per question (removes one wrong choice and shows the first
  letter of the answer).
* **Not on the web**: ads, Firebase, in-app review, the "exit app" dialog and
  the ad privacy settings entry.
* **Progress** is kept in `localStorage` under the same keys as the app and the
  previous web version (`language`, `resultCount`,
  `unlockedStage_<era>_<type>`, `readNoticeIds`, `dismissedNoticePopupIds`),
  so returning players keep their language, cleared stages and read notices.
  `webStorageVersion` marks that the one-time clean-up has run.
* **Keyboard**: 1–4 or A–D answer, Enter/Space continue, H hint, Esc back.
* The app has one dark theme, so the page is dark regardless of the system
  colour scheme.
